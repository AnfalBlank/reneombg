📊 Flowchart Operasional ERP MBG

Alur kerja sistem dari pemesanan bahan baku hingga pembayaran vendor

1. Alur Supply Chain (Dapur → Gudang → Vendor)

Dapur membuat permintaan bahan (IR), disetujui admin, lalu gudang mengirim barang via Delivery Order. Jika stok gudang kurang, otomatis generate Purchase Order ke vendor.

graph LR A[🏠 Dapur Buat IR] --> B{Admin Approve?} B -->|Ya| C[📦 DO Otomatis Dibuat] B -->|Tidak| Z1[❌ IR Ditolak] C --> D[🚚 Gudang Kirim Barang] D --> E[✅ Dapur Terima & Konfirmasi] E --> F[📊 Stok Dapur Update] C --> G{Stok Gudang Cukup?} G -->|Tidak| H[⚠️ Generate PO ke Vendor] G -->|Ya| D

2. Alur Purchase Order (PO)

Admin membuat PO, Finance approve, vendor kirim barang, gudang terima (GRN), stok update otomatis.

graph LR A[📝 Admin Buat PO] --> B[⏳ Status: Pending Approval] B --> C{Finance Approve?} C -->|Ya| D[✅ Status: Open] C -->|Tidak| Z[❌ PO Ditolak] D --> E[📦 Vendor Kirim Barang] E --> F[📋 Admin Buat GRN] F --> G[📊 Stok Gudang Update] G --> H[💰 Hutang ke Vendor Tercatat]

3. Alur Direct Delivery (Vendor → Langsung ke Dapur)

Untuk barang yang dikirim langsung ke dapur tanpa lewat gudang. Stok gudang tidak berubah, budget dapur langsung terpotong.

graph LR A[📝 PO Direct Delivery] --> B[✅ Finance Approve] B --> C[🚚 Vendor Kirim ke Dapur] C --> D[📋 GRN Direct Delivery] D --> E[💰 Budget Dapur Terpotong] D --> F[📊 Tercatat di Inventory Movement] D --> G[💳 Hutang Vendor Tercatat]

4. Alur Pembayaran Vendor

Setelah GRN diterima, hutang tercatat di Arus Kas. Finance upload bukti bayar, lalu approve untuk melunasi.

graph LR A[📋 GRN Diterima] --> B[💰 Hutang Tercatat - Belum Bayar] B --> C[📎 Finance Upload Bukti] C --> D[⏳ Status: Pending] D --> E{Finance Approve?} E -->|Ya| F[✅ Status: Lunas] E -->|Tidak| C F --> G[📱 Notifikasi WA ke Vendor]

5. Alur Price List & Harga Jual

Finance/Admin set harga beli dan jual per item dengan tanggal berlaku. Harga aktif otomatis dipakai saat buat PO dan DO.

graph LR A[📊 Set Harga di Price List] --> B[📅 Tanggal Berlaku] B --> C{Sudah Berlaku?} C -->|Ya| D[✅ Harga Aktif] C -->|Belum| E[⏳ Akan Berlaku Nanti] D --> F[🛒 Dipakai di PO] D --> G[🚚 Dipakai di DO - Harga Jual ke Dapur]

6. Alur Budget Dapur

Finance set budget per dapur per periode. Setiap IR dan Direct Delivery memotong budget. Jika habis, IR ditolak otomatis.

graph LR A[💰 Finance Set Budget] --> B[📅 Periode Aktif] B --> C[🏠 Dapur Buat IR] C --> D{Budget Cukup?} D -->|Ya| E[✅ IR Diproses] D -->|Tidak| F[❌ IR Ditolak - Budget Habis] E --> G[💸 Budget Terpotong] G --> H{Sisa < 20%?} H -->|Ya| I[⚠️ Warning ke Finance] H -->|Tidak| J[✅ Normal]

7. Alur Telegram Bot

User bisa login, buat IR, approve IR/PO, dan terima notifikasi langsung dari Telegram.

graph LR A[📱 Login via Telegram] --> B[✅ Akun Terhubung] B --> C[📎 Upload Excel SPPG] C --> D[📦 IR Otomatis Dibuat] B --> E[/approve] E --> F[✅ Approve IR/PO dari Telegram] F --> G[📢 Notifikasi ke User Terkait]

8. Pembagian Role & Akses

graph TD A[👑 Owner] --> A1[Executive Dashboard] A --> A2[Approval] A --> A3[Laporan] B[🔑 Super Admin] --> B1[Semua Fitur] C[📋 Admin Pusat] --> C1[Master Data] C --> C2[Purchase Order] C --> C3[Inventory] C --> C4[Supply Chain] C --> C5[Laporan] D[🏠 Admin Dapur] --> D1[Buat IR] D --> D2[Terima Barang] D --> D3[Dashboard Dapur] E[💰 Finance] --> E1[Approve PO] E --> E2[Pembayaran Vendor] E --> E3[Budget Management] E --> E4[Price List] E --> E5[Laporan Keuangan]
